# Aurora와 Twinkle 제품의 시장성 조사 및 판매 구성안

조사일: 2026-10-22 · 한국 시간 기준

현재 앱 판매와 홈페이지 구성을 주 대상으로 조사했다. Aurora 자체를 UI 키트로 판매하는 방향은 별도로 비교했다. 공개 경쟁 자료와 현재 홈페이지 소스에 기반한 가설이며, 고객 인터뷰나 실제 매출 검증을 마친 결과는 아니다.

## 1. 판단

Aurora의 시각적 완성도는 제품의 신뢰와 일관성을 뒷받침한다. 그러나 디자인만으로 시장 생존을 판단할 수는 없다. 현재 우선 검증할 방향은 **Pocket PDF의 한국어 문서 작업 경험**이다. 물타기 계산기는 기능 중복이 큰 만큼 작은 도구로 유지하며 검색 유입과 반복 사용을 검증한다. Aurora의 유료 UI 키트화는 별도 고객과 유통 경로가 필요한 사업이다.

이 우선순위는 매출 순위나 시장 점유율 추정이 아니다. 현재 보유 기능으로 제시할 수 있는 구매 이유의 구체성과 검증 비용을 기준으로 한 판단이다. 실제 설치·매출 데이터가 반대라면 우선순위를 바꿔야 한다.

| 대상 | 확인된 출발점 | 주요 경쟁 문제 | 우선 검증할 제안 |
|---|---|---|---|
| Pocket PDF | 홈페이지에 한국어 OCR, 도장·서명, 병합·분할, 기기 내 처리, 일회성 광고 제거를 명시 | 무료 스캔·서명이 이미 널리 제공됨. 광고 제거만으로 충분히 결제할지는 불명확 | 한국어 서류를 스캔·정리·서명해 제출하는 경험과 구독 없는 광고 제거 |
| 물타기 계산기 | 목표 평단가 역산, 종목별 통화·단위, 이력, 공유 리포트 | 직접 경쟁 앱도 역산·로컬 저장·여러 통화 제공 | 한국 사용자가 빠르게 입력하고 결과를 이해·공유하는 경험 |
| Aurora UI 키트 | 색상·글자·간격 체계와 실제 앱·웹 적용 사례 | 대형 키트는 완성 화면·코드·설치 도구까지 제공 | 한국어 유틸리티 앱의 숫자·입력·문서 작업 화면에 특화한 작은 패키지 |

## 2. 공개 자료에서 확인한 경쟁 상황

가격은 조사 당시 공개 페이지에 표시된 값이며 국가·세금·결제 주기·스토어에 따라 달라진다. 공개 상품 구성은 공급과 경쟁의 증거이지, Aurora의 수요나 경쟁사의 수익성을 증명하지 않는다.

## 3. 먼저 팔아볼 대상과 메시지

Pocket PDF의 첫 고객 가설은 ‘안드로이드에서 한국어 서류를 정리하고 서명해서 제출하는 개인 사용자·프리랜서’다. 기업 보안 인증이나 법적 전자서명 효력을 전제로 구매하는 조직은 현재 조사로 뒷받침할 수 없다.

사용 장면은 다음 세 가지로 좁힌다.

1. 종이 문서를 촬영하고 한국어 텍스트를 검색·복사한다.
2. 받은 PDF에 서명이나 도장을 배치하고 저장한다.
3. 제출할 문서들을 합치거나 필요한 페이지만 추출한다.

기존 기능을 사용 장면으로 묶은 제안이다. 기능 사이에 원활한 연결이 실제로 되는지는 앱에서 검증해야 한다. ‘한 번에 완료’, ‘30초 만에 완료’ 같은 표현은 관찰로 입증하기 전에는 사용하지 않는다.

추천 메시지 초안:

> PDF에 서명하고, 합치고, 필요한 페이지만 꺼내세요.
>
> 한국어 문서 스캔부터 도장·서명까지. 문서 처리는 내 기기에서, 일곱 가지 도구는 무료로 사용하세요.
>
> [Google Play에서 무료로 받기] [실제 작업 화면 보기]
>
> 무료 기능에 광고 포함 · 광고 제거는 1회 결제 · 로그인 없음

현재 홈페이지 설명을 바탕으로 한 초안이다. 광고 위치·정확한 결제 금액·구매 복원 조건·문서 처리 범위는 출시 앱과 맞춰 확인한 뒤 게시한다. ‘문서를 외부 처리 서버에 업로드하지 않는다’와 ‘앱이 어떤 데이터도 전송하지 않는다’는 서로 다른 주장이다. 광고·분석 SDK가 있는 경우 문서 처리와 그 데이터 흐름을 구분해 설명한다.

## 4. 홈페이지와 상세 페이지 구성

현재 홈은 Hero → Apps → Founder → How → Names 순서다. 이미 제품 구획이 앞쪽에 있으므로 전체 재구축보다 첫 화면의 메시지와 제품 카드의 우선순위부터 실험할 수 있다. 다만 브랜드 홈의 대표 제품을 결정하기 전 실제 유입·매출 자료를 확인하는 것이 좋다.

[Nielsen Norman Group의 홈페이지 원칙](https://www.nngroup.com/articles/homepage-design-principles/)은 첫 화면에서 사이트의 목적·사용자 가치·행동 경로를 명확히 전달하도록 권고한다. 이를 근거로 아래 구조를 제안하며, 이 구조 자체의 전환 상승은 아직 검증되지 않았다.

### 브랜드 홈

| 순서 | 내용 | 역할 |
|---|---|---|
| 1 | ‘PDF 작업부터 투자 계산까지, 필요한 일을 간단하게.’ + 실제 앱 화면 + 앱별 진입 버튼 | 처음 온 사람이 무엇을 얻을 수 있는지 이해 |
| 2 | Pocket PDF와 물타기 계산기 카드. 기능 개수보다 대표 작업과 사용 조건 | 자신의 문제에 맞는 제품 선택 |
| 3 | 실제 사용 예시와 결과물 | 설명에 대한 증거 제공 |
| 4 | 가격 방식·문서 처리·로그인 여부를 앱별로 정확히 표시 | 설치 전 의문 해소 |
| 5 | 운영자·문의·업데이트 기록 | 유지보수 신뢰 |
| 6 | Aurora와 브랜드 이야기 | 제품에 관심을 가진 사람에게 배경 제공 |

‘스스로 빛나다’는 작은 브랜드 문구로 유지할 수 있다. ‘1인 개발자 + AI’는 운영자 소개에서 다룬다. 고객에게 첫 번째로 전달할 정보는 자신의 작업을 어떻게 끝낼 수 있는지다.

### Pocket PDF 상세 페이지

| 순서 | 구성 | 구체적인 자료 |
|---|---|---|
| 1 | 작업 결과를 말하는 제목 + 무료 설치 버튼 | 서명한 PDF 등 실제 화면 한 장 |
| 2 | 짧은 작업 시연 | 열기 → 도장·서명 → 저장. 촬영한 실제 동작 |
| 3 | 대표 사용 장면 3개 | 서류에 서명 / 문서 합치기 / 한글 스캔 |
| 4 | 무료와 결제의 정확한 차이 | 무료 기능, 광고 여부, 광고 제거 가격, 1회 결제 표시 |
| 5 | 비교와 신뢰 | 파일 처리 위치, 로그인, 지원 언어·기기. 검증한 사실만 표시 |
| 6 | FAQ | 파일 보관 위치, 오프라인 범위, 구매 복원, OCR 한계, 지원되지 않는 편집 |
| 7 | 설치 버튼과 지원 경로 | Google Play, 문의, 개인정보 처리방침 |

개별 기능을 설명하는 현재 화면은 재사용한다. 모든 기능에 같은 길이의 화면 설명을 붙이기보다 가장 중요한 세 작업을 먼저 보여준다. 후기·사용자 수는 확인 가능한 실제 자료가 있을 때만 추가한다. 후기가 없다면 작업 시연과 공개 변경 기록을 사용한다.

### 스토어에서 이어지는 구성

첫 스크린샷은 ‘내가 끝낼 일’, 두 번째는 실제 작업, 세 번째는 무료·광고·일회 결제 조건을 보여준다. 예시 순서는 ‘PDF 서명과 도장 → 여러 PDF 합치기 → 한글 검색 스캔 → 문서는 기기에서 처리 → 무료 기능과 광고 제거’다. 11개 언어 지원은 현지화된 상세 설명에서 보조 정보로 사용한다.

검색 의도가 분명한 ‘안드로이드 PDF 도장’, ‘PDF 합치기’, ‘한글 검색 PDF 스캔’에 맞춘 콘텐츠와 상세 페이지를 실험한다. 검색량은 이번 조사에서 확인하지 않았으므로 인기 키워드라고 단정하지 않는다. 커뮤니티에서는 실제 작업 가이드를 제공하고 게시 규칙을 지킨다. 유료 광고는 설치당 수익이 확인된 뒤 소액으로 검증한다.

## 5. 결제 구성과 수익성

현재 약속인 기본 도구 무료 + 광고 제거 1회 결제를 첫 검증 대상으로 유지한다. 기존 무료 기능을 갑자기 잠그거나 구독으로 바꾸는 방안은 제안하지 않는다. 작업을 마친 뒤 광고 제거의 효용과 가격을 보여주되, 결제를 유도하기 위해 작업 중단 광고를 늘리면 안 된다.

광고 제거 가격은 현재 앱의 실제 금액을 확인하지 못했다. 신규 가격 검토가 필요하다면 4,900원·7,900원·9,900원을 **지불 의사 조사 후보**로 삼을 수 있다. 이는 경쟁 조사로 입증된 적정 가격이 아니다. 실제 판매 실험은 기존 구매자 권리, 지역 가격과 환불을 고려하여 설계한다.

수익성은 다음 계산으로 판단한다.

> 설치당 기여액 = 설치→결제 전환율 × 결제 1건당 순기여액 + 설치당 광고 순기여액 − 설치당 기타 변동비
>
> 사업의 잔여 기여액 = 설치 수 × 설치당 기여액 − 유입 비용 − 고정 운영비 − 개발·지원 노동비

**계산 예시일 뿐 실적·예측이 아님:** 결제 1건당 순기여액을 5,000원, 광고 기여와 기타 변동비를 0원으로 가정한다. 순기여액에는 스토어 수수료·세금·환불 등 판매 관련 차감을 반영했다고 가정한다.

| 설치→결제 전환율 가정 | 설치당 기여액 | 10,000설치의 결제 기여액 |
|---|---:|---:|
| 1% | 50원 | 50만원 |
| 3% | 150원 | 150만원 |
| 5% | 250원 | 250만원 |

이는 고정비·유입 비용·개발자 노동비 차감 전이다. 3% 가정에서는 설치당 유입 비용이 150원이면 그 단계에서 기여액을 모두 소진한다. ‘월 1만 설치’ 자체가 생계가 되는 사업을 뜻하지 않는다. 일회 결제는 같은 고객에게서 매달 반복되지 않으므로 새 고객 유입과 유지보수 비용을 함께 계산해야 한다.

추가 유료 기능은 반복 사용자가 실제로 요청한 일괄 처리·반복 작업 설정 등에서 찾는다. 이런 기능은 현재 제품에 있다고 주장하지 않으며, 인터뷰와 사용 관찰 후 개발 여부를 결정한다.

## 6. Aurora 자체를 판매하는 경우

범용 보라색 UI 키트는 큰 라이브러리와 무료 대안 사이에서 구매 이유를 만들기 어렵다는 판단이다. 판매한다면 ‘한국어 유틸리티 제품을 일관되게 만드는 화면·컴포넌트 패키지’로 범위를 좁힌다. 한국어 지원만으로 유료 수요가 입증되는 것은 아니다.

제안할 최소 유료 패키지는 다음과 같다. 모두 신규 상품 구성 제안이며 현재 제공 중이라는 뜻이 아니다.

- 한국어·영어와 라이트·다크를 포함한 완성 화면 12~15개.
- 금액·통화·수량 입력, 계산 결과, 기록 목록, 문서 선택·정렬 등 대표 작업 컴포넌트.
- 빈 화면·오류·로딩·키보드 포커스·접근성 상태.
- Figma 변수와 하나의 지원 코드 플랫폼을 일치시킨 샘플 프로젝트.
- 실행 방법, 지원 버전, 상업 이용 범위, 업데이트·지원 범위를 명시한 문서.
- 무료 샘플 2~3개와 실제 동작 데모.

코드 플랫폼은 구매 후보 인터뷰에서 선택한다. 처음부터 React와 Android Compose를 모두 제품으로 유지하는 것은 지원 비용을 늘린다. 이미 보유한 구현 자산과 초기 구매자의 작업 환경이 겹치는 쪽부터 시작한다.

판매 페이지 순서: 누구의 어떤 구현 작업을 돕는가 → 완성 화면 데모 → 제공 파일과 코드 → 무료 샘플 → 호환성·품질 근거 → 가격·라이선스·지원 → FAQ.

가격 인터뷰 후보는 개인용 49,000원 또는 79,000원 정도로 시작할 수 있으나 검증된 시장 가격이 아니다. 대형 라이브러리의 $149와 단순 환율 비교해 적정가를 정하지 않는다. 가격에 앞서 외부 개발자가 샘플을 설치해 실제 프로젝트에 적용하는지 확인한다.

## 7. 30일 검증 계획

기간은 실행 계획이며, 30일만으로 생존 가능성을 확정한다는 뜻은 아니다. 충분한 유입이 없으면 통계적 실험을 연장하고 사용 관찰을 우선한다.

| 기간 | 할 일 | 판단 자료 |
|---|---|---|
| 1주 | 최근 30일 설치·유입·활성 사용·광고·결제·환불 확인. 목표 사용자 5명에게 실제 문서 작업 관찰 | 유입이 없는지, 설치 후 실패하는지, 사용해도 결제하지 않는지 구분 |
| 2주 | Pocket PDF 제목·첫 스크린샷을 ‘서명·제출’ 메시지와 기존 버전으로 비교 | 스토어 방문→설치. 나머지 조건은 가능한 한 고정 |
| 3주 | 첫 작업 완료율과 실패 이유 확인. 실제 가격을 보여주는 일회 결제 제안 검증 | 작업 시작→완료, 결제 노출→구매, 환불 |
| 4주 | 설치 코호트의 재작업·지원 요청·순기여액 비교 | 유지·수정·확대 여부 |

[Google Play 스토어 실험](https://support.google.com/googleplay/android-developer/answer/12053285?hl=en)은 문구·이미지 변형을 비교할 수 있다. [맞춤 스토어 등록정보](https://google.play/business/customstorelistings/)는 유입 대상에 맞는 설명을 보여줄 수 있다. 가격 실험과 스토어 소재 실험을 혼동하지 않는다.

권장 측정 항목: 유입 출처별 상세 페이지 조회·스토어 이동, 스토어 방문→설치, 첫 작업 시작→완료, 30일 내 추가 작업, 결제 노출→구매, 환불, 지원 시간. 문서 내용·파일명·금액 등 작업 데이터를 측정값으로 수집하지 않는다. 구현 여부와 동의·데이터 약속은 별도 검토한다.

현재 웹 소스에는 스토어 referrer와 GA 설정이 있으나, 실제 콘솔 수치나 앱 내부 이벤트 구현은 이번 조사에서 확인하지 않았다. 웹 클릭과 앱 설치·구매를 동일 사용자로 정확히 연결할 수 있다고 가정하지 않는다.

판정 원칙:

- 설치는 늘고 작업 완료가 떨어지면 홍보 확대보다 제품 오류·사용성을 먼저 수정한다.
- 작업은 완료하지만 결제가 없으면 작업 빈도·광고 제거의 가치·가격을 살핀다.
- 전환은 괜찮아도 유입이 없으면 검색·스토어 노출과 유통을 검증한다.
- 확보 비용을 빼고도 유지보수와 운영자 보상을 감당할 기여액이 반복해서 남을 때 확대한다.
- 소수의 결제나 기간별 우연한 차이를 통계적 승리라고 표현하지 않는다. 표본 크기와 불확실성을 같이 본다.

## 8. 이번 조사로 확인하지 못한 것

Twinkle 두 앱의 Google Play 페이지는 연구 도구에서 직접 조회되지 않았다. 출시 여부·기능은 현재 홈페이지 소스의 선언을 기준으로 했으며 앱 바이너리를 직접 검증하지 않았다. 실제 가격, 설치 수, 별점·후기, 매출, 광고 수익, 결제율, 재사용률, 획득 비용, 월 유지보수 시간은 확인하지 못했다. 검색량·시장 규모·경쟁사 매출도 추정하지 않았다.

따라서 현재 결론은 **Pocket PDF의 구체적인 문서 작업과 투명한 일회 결제를 먼저 검증할 가치가 있다**는 것이다. Aurora 디자인을 유지하면서 고객의 작업·증거·가격을 전면에 배치하는 구성이 가장 작은 비용으로 시험할 수 있는 다음 단계다.
